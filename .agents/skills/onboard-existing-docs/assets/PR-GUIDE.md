# PR description: review guide

This skill produces a PR that onboards a downstream repository into the
Copier-based documentation management solution. To help human reviewers
focus their attention, include a `## For reviewers` section in the PR
description, placed **before** the `## Items requiring human action` section.

**Only list files that were actually added or modified in the current run.**
Omit rows for files that do not apply to this particular repository.

Organize the files into three priority tiers:

## High priority — verify correctness

These files contain project-specific values or re-applied customizations that
require human judgment. List each applicable file with a brief note explaining
what was changed:

| File | What to verify |
|---|---|
| `docs/conf.py` | Project-specific values filled in by Copier (project name, author, URLs, community links). Verify all `html_context` entries match the project. |
| `docs/conf.py` (customizations) | Re-applied downstream customizations: custom Sphinx extensions, extra `html_context` entries, custom `html_theme_options`. Verify these were correctly carried forward from the original. |
| `docs/Makefile` (customizations) | Re-applied custom Makefile targets. Verify they still work with the new template structure. |
| `docs/requirements.txt` (customizations) | Re-applied extra Python dependencies. Verify version pins are correct. |
| `.copier-answers.yml` | Records all Copier answers. Verify each value matches the project. **Do not edit this file manually.** |

## Medium priority — structural and build changes

These files follow predictable patterns but affect build behavior:

| File | What to verify |
|---|---|
| `docs/Makefile` | Standard build targets from the template. Verify `make html` succeeds. |
| `docs/requirements.txt` | Standard dependencies from the template. Verify no conflicts with re-applied extras. |
| `docs/.gitignore` | Merged ignore patterns. Verify downstream-specific patterns were preserved. |
| `.readthedocs.yaml` | RTD build configuration. Verify the Python version and build settings are correct for the project. |

## Low priority — copied from the template

These files are copied verbatim from the
[platform-engineering-documentation-files](https://github.com/canonical/platform-engineering-documentation-files)
template and should not deviate from upstream. Wrap them in a collapsed
`<details>` block in the PR description:

```markdown
<details>
<summary>Low priority — copied verbatim from the template (click to expand)</summary>

- `docs/_dev/*` — Developer tooling (vale, pa11y, pre-commit, pymarkdown, sphinx-stack updater)
- `docs/_templates/*` — HTML header and footer templates
- `docs/release-notes/template/*` — Release note artifact templates
</details>
```

## Items requiring human action

Include a checklist of actions the PR author or reviewer must complete
before merging:

```markdown
## Items requiring human action

- [ ] Verify all values in `.copier-answers.yml` match the project
- [ ] Verify `make html` succeeds with no warnings
- [ ] Set up Read the Docs project (if not already configured)
- [ ] Review re-applied downstream customizations in `docs/conf.py`
- [ ] Delete the backup at `/tmp/docs-backup/` after confirming everything works
- [ ] Update any hardcoded references to old documentation URLs
```
